# 2nd ComputeConfig - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
# ComputeConfig of the LagrangianDualSolver; it mostly is the
# ComputeConfig of the inner Solver, which is a [Parallel]BundleSolver.
# LDCfg.txt already has intDoEasy=0, which is what these all-easy instances
# need; what it does not have is an intWZNorm these instances can live with.
# That parameter says which norm of the residual the stopping condition uses
# and how dblNZEps is read, and the 8 of the 10 of LDCfg.txt asks for a
# threshold scaled by the norm of the first full subgradient, which was set
# for the plan4res instances. Here the subgradients of the units are the
# productions on the very rows the demand sits on, so that norm is 7.27e+06
# against an aggregate of 1.96e+04, and 1e-2 of it stops the Bundle at the
# first iteration on a value two orders of magnitude below the optimum. Read
# as the absolute value it is on develop, the duals of these instances
# converge in 50 to 600 iterations on the value the MILP computes.

*LDCfg.txt +

1  # f_diff == 1 ==> only the entries listed below are changed

1 # number of integer parameters

intWZNorm 2 # the threshold of the residual is the absolute one

0 # number of double parameters
