#
# Cross-check BlockSolverConfig for a PURE-BINARY BinaryKnapsackBlock: it
# attaches EVERY solver / formulation that must give the SAME integer optimum,
# so that a single sweep cross-checks them all (see batch):
#
#   - :MILPSolver                         exact MIP (the reference optimum)
#   - CoreDPBinaryKnapsackSolver          exact core / non-dominated-state DP
#     re-solving with all its reoptimization (intReopt 3: the previous
#     solution as the incumbent, and returned with no solve when the changes
#     or a bound show that it is still optimal)
#   - RECORDBinaryKnapsackSolver, which hands the core to RECORD under the
#     same reoptimization; a build without RECORD leaves it out of the run,
#     which says so [see Solver::has_Solver()]
#   - GreedyRelaxationBinaryKnapsackSolver  relaxation: must BRACKET the optimum
#   - BranchAndXSolver, once per exploration mode (best-/depth-/breadth-first,
#     parallel depth-first, per-node parallel solvers): all are exact and must
#     hit the same optimum (the reduced-cost fixing each does internally is a
#     detail of the relaxation, not a separate mode).
#   - BranchAndXSolver again, on a few of those modes but driven by the
#     incremental greedy relaxation (InnerBSCfg-incr.txt): same optimum.
#   - BranchAndXSolver in reoptimization mode (intReoptimize), which retains
#     the tree and re-seeds from its fenced frontier at each re-solve: same
#     optimum after every runtime Modification.
#
# The per-solver ComputeConfig are factored into the *Cfg.txt fragments (the
# MILP/DP/GR ones are shared with BSPar-mixed.txt, the core DP and RECORD
# share CDPCfg-reopt3.txt) and the BX modes share BX-baseCfg.txt, overriding
# only the mode-specific parameters via '*BX-baseCfg.txt +': no duplication.
# NOTE: an overriding ComputeConfig that is not the last in the list must end
# with the '*' extra-Configuration pointer, or the parser runs into the next.
#
# - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
